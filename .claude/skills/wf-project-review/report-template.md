# Review 報告章節(固定)

檔案:`docs/reviews/YYYY-MM-DD.md`。標題為「專案 Review — YYYY-MM-DD」。章節順序與標題固定:

## 1. 摘要
三到五句話:專案現況、最大的風險。

## 2. 專案與目標
Review 所理解的專案與目標,以及與使用者說法的落差。目標在文件中找不到時,寫「未見於文件」。

## 3. Agent 架構現況
範圍:skills、subagents、`CLAUDE.md`/`AGENTS.md`、settings、plugin、MCP。用表格或條列列出現有項目,再列出問題與證據(路徑)。

## 4. 文件維護狀況
依 wf-project-review 第 1 步第 4 點的五項標準,各給「良好 / 有問題 / 資料不足」與證據。

## 5. Grill 發現
訪談中浮現的矛盾、缺口與使用者的決定。每項註明:問題 → 使用者的回答或「未解決」。

## 6. 建議
分三小節:**刪改**、**Agent 架構**、**未來發展**。每條:建議內容、優先級(高 / 中 / 低)、理由、涉及的檔案。
